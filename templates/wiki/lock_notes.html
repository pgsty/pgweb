从锁冲突到实际等待

这 {{ total }} 种是锁模式，由 8 种表级模式和 4 种行级模式组成；它们不是 pg_locks.locktype 的全部锁对象类别。锁模式、锁对象和等待事件分别回答「怎样锁」「锁什么」和「正在等什么」。

  • 普通 SELECT 通过 MVCC 读取，不取得这里的行级锁，但仍需取得表级 ACCESS SHARE 锁。
  • SELECT … FOR UPDATE / SHARE 等行锁子句还会取得表级 ROW SHARE 锁；UPDATE / DELETE 还会取得表级 ROW EXCLUSIVE 锁。因此，行操作也可能被表锁挡住。
  • 组合矩阵按操作同时取得的表锁，将常见行锁组合分组，再按「表锁冲突，或同一行上的行锁冲突」判断。红色 × 来自表锁，即使操作不同行也会冲突；琥珀色 ● 只在两边锁定同一行时冲突。它列出常见的 14 个比较项，并不表示还有两种额外锁模式。
  • 矩阵比较不同事务，同一事务不会因自身持有的模式而按此矩阵阻塞。锁通常持有到事务结束；回滚到保存点会释放该保存点之后取得的锁。行锁、事务和保存点的细节见显式锁定。
  • 矩阵只描述锁模式能否共存。等待队列中的先来请求也可能让后来的请求排队；实际行为还受对象、命令阶段、事务状态及 NOWAIT / SKIP LOCKED 等选项影响。

咨询锁

应用自行约定键值，可以选择共享或独占、会话级或事务级。参见咨询锁。

谓词锁

SIReadLock 用于可串行化快照隔离的依赖检测，不按这里的矩阵阻塞写入。参见可串行化隔离级别。

内部同步

页级锁、轻量锁等还参与数据库内部同步。它们不属于这 12 种 SQL 锁模式；排查时结合统计与等待事件。

查看谁在阻塞谁

下面的只读查询列出当前有阻塞者的会话。pg_blocking_pids() 同时考虑已持有冲突锁的会话和排在前面的冲突请求；进一步检查对象与模式时，结合 pg_locks。

SELECT pid, usename, wait_event_type, wait_event,
       pg_blocking_pids(pid) AS blocking_pids,
       query
FROM pg_stat_activity
WHERE cardinality(pg_blocking_pids(pid)) > 0
ORDER BY pid;

会话和查询文本的可见范围取决于当前用户权限。行锁通常不会直接逐行列在 pg_locks 中，行锁等待常表现为等待持锁事务结束。
