{% endblock presskit_toc %} {% block presskit_release_heading %}PostgreSQL 19 正式发布！{% endblock presskit_release_heading %} {% block presskit_content %}

2026 年 11 月 19 日 — PostgreSQL 全球开发组今日宣布 PostgreSQL 19 正式发布。这是世界上最先进的开源数据库的最新版本。

PostgreSQL 在关键业务中的应用持续快速增长。为满足这一需求，PostgreSQL 19 简化了此类大规模工作负载的管理与开发。本次发布引入了 REPACK (CONCURRENTLY) 命令，让用户能够在不中断现有业务的情况下，针对当前工作负载优化表。新增的 pg_plan_advice 扩展让用户能够更好地控制查询计划的稳定性与查询性能。本次发布也为开发者带来了许多实用功能，包括在备库上支持“读己之写”一致性，以及可节省一次网络往返的“获取或创建”操作。

PostgreSQL 核心团队成员 Jonathan Katz 表示：“30 多年来，全球开源社区共同打造 PostgreSQL，使其成为各类组织放心托付最关键数据的数据库。PostgreSQL 19 延续了这一对可靠性的承诺，为用户提供了新的方式，使其能够在不中断业务的情况下管理工作负载，并构建横跨多个系统的应用程序。”

PostgreSQL 是一个以可靠性、健壮性和可扩展性著称的创新数据管理系统。经过全球开发者社区 30 年的开源开发，它已成为各种规模组织首选的开源关系数据库。

简化工作负载管理

频繁更新和删除的表可能积累大量未使用空间，形成所谓的“膨胀”（bloat），这也可能显著影响查询性能。此前通常使用 VACUUM FULL 和 CLUSTER 命令处理这一问题，但这些操作存在局限，例如在清理完成前会阻止对表的访问。PostgreSQL 19 引入了 REPACK 命令，既能回收这些空间，也能按照索引顺序重新排列表中的数据；使用 REPACK (CONCURRENTLY) 还可以在不阻塞读写的情况下完成这些操作。REPACK 取代了 VACUUM FULL 和 CLUSTER 命令，后两者仍予保留，以兼容现有用法。

PostgreSQL 查询规划器通常会为每条查询选择高效的执行计划，但计划可能随数据变化而改变，有时新计划反而更慢。PostgreSQL 19 新增的 pg_plan_advice 扩展可以稳定查询计划的选择，并通过简洁的“计划建议”（plan advice）语言试验不同的执行计划。配套的 pg_stash_advice 扩展用于存储这些建议，并根据查询标识符自动将建议应用到查询上，从而无需修改应用程序就能修正低效的执行计划。

PostgreSQL 19 还增强了 autovacuum 应对繁忙系统的能力。autovacuum 现在可以使用并行工作进程清理索引，由新增的 autovacuum_max_parallel_workers 参数控制；它还会使用新的评分机制决定优先处理哪些表。读取表的查询现在可以在执行过程中，自动在可见性映射中将页面标记为全部可见，减少后续 vacuum 的工作量。此外，vacuumdb --analyze-only 在未指定表时，现在也会分析分区表。

本次发布新增了多个用于监控工作负载的视图，包括按锁类型提供统计信息的 pg_stat_lock、显示恢复状态的 pg_stat_recovery，以及展示 autovacuum 如何确定表处理优先级的 pg_stat_autovacuum_scores。EXPLAIN ANALYZE 新增的 IO 选项及相应的 auto_explain 设置可以报告异步 I/O 活动。PostgreSQL 19 还会在 pg_stat_wal、EXPLAIN (ANALYZE, WAL) 以及 vacuum 和 analyze 的日志事件中，报告为记录全页镜像而写入的 WAL 数据量。

分布式数据改进

此前，启用逻辑复制通常需要重启 PostgreSQL 服务器，这可能中断生产业务。PostgreSQL 19 简化了逻辑复制的初始化：创建第一个逻辑复制槽时，会自动将实际生效的 WAL 级别提升为 logical。通过新增的 effective_wal_level 参数，可以查看当前生效的 WAL 级别。

PostgreSQL 19 还支持对序列值进行逻辑复制，可以在 CREATE PUBLICATION 中使用 FOR ALL SEQUENCES 发布序列。CREATE PUBLICATION 还新增了 EXCEPT 子句，用于在使用 FOR ALL TABLES 发布所有表时排除指定的表。CREATE SUBSCRIPTION 现在可以通过 SERVER 子句，从外部服务器定义中获取连接设置，例如使用 postgres_fdw 定义的外部服务器。此外，新增的 retain_dead_tuples 订阅选项让 PostgreSQL 能够检测与并发删除相冲突的更新操作，这些冲突会计入 pg_stat_subscription_stats 的统计数据。

对于将读请求发送到备库的应用，PostgreSQL 19 通过新增的 WAIT FOR LSN 命令提供“读己之写”（read-your-writes）一致性。备库上的会话可以使用 WAIT FOR LSN，等待备库将预写日志（WAL）重放至指定的日志序列号（LSN）后再执行查询，从而让应用读到自己刚刚写入主库的数据。

PostgreSQL 19 也改进了对外部表的查询。借助新增的 import_stats 选项，postgres_fdw 在执行 ANALYZE 时，可以直接从远程服务器导入表的统计信息，无需对远程表中的行进行采样，从而帮助查询规划器选择更优的执行计划。

开发者体验与性能增强

PostgreSQL 19 新增了 INSERT ... ON CONFLICT DO SELECT，让 RETURNING 子句能够返回与插入操作发生冲突的已有行，简化常见的“获取或创建”（get or create）模式。COPY 现在可以将数据输出为 JSON 格式，包括输出为一个 JSON 数组。SQL/JSON 路径语言新增了 lower()、upper()、replace()、split_part() 和 btrim() 等字符串方法。此外，lead()、lag()、first_value()、last_value() 和 nth_value() 这些窗口函数现在可以通过 IGNORE NULLS 跳过 NULL 值。random() 函数现在还可以生成指定范围内的随机日期和时间戳。

本次发布还让许多工作负载无需修改应用程序就能获得性能提升。PostgreSQL 19 改进了外键检查的性能，测试中批量插入的速度接近原来的两倍。查询规划器也新增了多项优化，例如在不存在 NULL 值时，将 NOT IN 子句转换为更高效的反连接；以及在连接之前执行预聚合（eager aggregation），减少需要处理的行数。PostgreSQL 19 还进一步改进了 PostgreSQL 18 引入的异步 I/O 子系统。当 io_method 设置为 worker（默认值）时，PostgreSQL 会在新增的 io_min_workers 与 io_max_workers 参数设定的范围内，自动调整 I/O 工作进程的数量。这两个参数取代了原有的 io_workers 参数。在多通道工作负载中使用 LISTEN 与 NOTIFY 交换通知时，可扩展性也有所提升。

最后，新增的 password_expiration_warning_threshold 参数会在用户密码即将过期时发出警告。

其他重要变更

PostgreSQL 19 新增了对服务器名称指示（SNI）的服务端支持，使单个 PostgreSQL 服务器可以根据客户端连接时使用的主机名，提供不同的 TLS 证书。可以在新增的 pg_hosts.conf 文件中，将主机名映射到相应的证书和密钥。PostgreSQL 19 现在还会在 md5 密码认证成功后发出警告，可通过 md5_password_warnings 参数关闭。md5 密码认证在 PostgreSQL 18 中已被弃用，并将在未来版本中移除。如果需要使用密码认证，请使用 SCRAM 认证。本次发布还移除了对 RADIUS 认证的支持。

即时编译（JIT）现已默认关闭，因为实践证明，PostgreSQL 用于判断何时启用 JIT 的成本估算并不可靠。如果运行大量大型分析查询，可以考虑启用 JIT。当 PostgreSQL 编译时启用了 LZ4 支持，默认的 TOAST 压缩方法现在为 lz4。

PostgreSQL 19 还新增了许多其他功能与改进，可能同样适合您的使用场景。完整的新功能与变更列表请参阅发行说明。

许可证

PostgreSQL 使用 PostgreSQL 许可证，这是一种类似 BSD 的宽松许可证。该许可证已获 OSI 认证，因其灵活且适合商业使用而广受赞誉，因为它不限制 PostgreSQL 在商业和专有应用中的使用。再加上多家公司支持以及代码公共所有权，这使 PostgreSQL 对希望在自身产品中嵌入数据库的厂商极具吸引力，无需担心费用、供应商锁定或许可条款变化。
