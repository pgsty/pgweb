# PostgreSQL 文档检索

分支 `codex/dash-doc-search` 在 `/search/` 实现类似 Dash 的文档检索：左侧实体分类，中间即时结果，右侧定义预览。数据由现有 `docs` 表提取，查询在本站 PostgreSQL 数据库完成。无需独立搜索服务或外部 API。

## 使用

| 输入或操作 | 效果 |
| --- | --- |
| `work_mem`、`逻辑复制槽` | 搜索当前选择版本的实体名称、别名、定义和章节正文 |
| `pg: work_mem` | 使用 `core_version.current` 指定的版本 |
| `pg17: work_mem` | 严格限定 PG17；支持当前已建立索引的 PG14–19，测试版有明确标记 |
| `pg18: kind:guc 内存` | 同时约束版本、类别与关键词；类别也可以用左侧筛选 |
| `23505`、`unique_violation` | 同一个错误条件的代码或名称 |
| `int4`、`timestamptz` | 查到对应类型定义；带时区和不带时区的类型分别处理 |
| `->>`、`@>`、`\d+` | 保留符号；psql 命令区分 `\dD` 与 `\dd` |
| `"逻辑复制"` | 按连续文本匹配 |
| 清空输入，选择类别 | 按类别浏览名称索引 |
| 单击 / 方向键 | 预览对应定义 |
| 回车 / 双击 / “打开完整文档” | 打开正文并定位锚点 |
| `⌘K` / `Ctrl+K`、`/` | 聚焦搜索；文档阅读页的 `⌘K` 带入当前阅读版本 |

查询、版本和类别写入 URL，支持分享、刷新和浏览器前进后退。输入有防抖、取消旧请求及中文输入法处理。移动端在结果与预览之间切换。页面也输出服务端结果，禁用 JavaScript 后仍可提交搜索并打开正文。

## 数据与提取

只增加两个可重建的派生表：

| 表 | 用途 |
| --- | --- |
| `search_indexedpage` | 原文页面外键、内容及提取器版本的摘要、索引时间 |
| `search_searchentry` | 版本、实体身份、类别、名称、别名、签名、正文片段、锚点、清洗后的预览和 `tsvector` |

分类为配置参数、SQL 命令、函数与例程、运算符、数据类型、系统目录与视图、错误代码、psql 命令、命令行工具、选项与环境变量、官方模块与扩展、访问方法、过程语言、语法与表达式、章节与指南。

提取依据是手册的结构：GUC 定义列表、函数与运算符表、类型表、错误码表、SQL reference、文档化的系统关系与章节标题。普通正文中的函数名称不会自动变成定义。长章节按结构拆分，保留嵌套章节前后的正文；同一实体的重载和多处定义在结果中折叠，预览提供其他签名与版本入口。类别数字是本地文档的提取结果，不能当作运行中 PostgreSQL 的对象总数。

已有锚点优先保留；缺少锚点的定义使用内容摘要生成 `SEARCH-*` 标识。索引与阅读页使用同一个锚点生成函数，阅读时不回写 `docs.content`。定义文字变化后，生成的锚点可能变化；它不是独立于原文的永久实体 URL。

名称精确匹配、别名、名称前缀优先于正文相关性。中文使用 jieba 与少量 PG 术语词典，英文与标识符使用 `simple` 文本搜索配置；GIN 索引支持全文及别名查询，`pg_trgm` 在没有结果时给出限定于同版本的近似名称。数值错误码和纯符号不做模糊纠错。

## 建立与更新索引

依赖见根目录 `requirements.txt`，新增 Beautiful Soup 和 jieba；数据库需要 `pg_trgm`，初始迁移在不存在时创建。安装依赖后，在项目根目录执行：

```bash
.venv/bin/python manage.py migrate search
.venv/bin/python manage.py index_docs --versions 18 17 16 15 14 19
.venv/bin/python manage.py runserver 127.0.0.1:8011
```

不指定 `--versions` 时处理所有已经导入的 PG14 及以上手册；`tree=0` 的 devel 副本不重复索引。纯目录页、书末索引、SVG 和被阅读路由转到其他大版本的重复发行说明不作为正文条目。

```bash
# 提取预览，不写入索引。
.venv/bin/python manage.py index_docs --versions 18 --dry-run

# 原文更新后增量处理；没有变化的页面不重写。
.venv/bin/python manage.py index_docs --versions 18

# 需要重新生成所有派生条目时。
.venv/bin/python manage.py index_docs --versions 18 --force
```

提取结果按版本在事务内发布，通过 advisory lock 串行化同版本的索引发布，并锁定变化的源页面核验快照。未变化的定义尽量保留内部 ID。SQL 外键级联处理原始文档导入工具的删除；触发器在正文、标题、路径或版本变化时撤下对应旧索引，避免展示失效的定义。

**导入文档后必须运行 `index_docs`。** 触发器只失效旧数据，不在文档写入事务内执行分词与提取；重建前，变化页面暂时不会出现在搜索结果中。`tools/docs/docload.py` 完成有变化的导入后会打印重建命令。其余导入入口也应将此命令接到导入流程末尾。

修改分词或提取规则时递增 `PIPELINE_VERSION`，再运行增量索引。索引命令不抓取网络内容，也不修改原始文档正文。三个 search 迁移均提供反向操作；回滚到 `search zero` 会删除派生索引，保留原手册和可能已被其他功能使用的 `pg_trgm`。

## 验证与当前边界

```bash
.venv/bin/python manage.py test pgweb.search pgweb.docs --noinput
.venv/bin/python manage.py check
.venv/bin/python manage.py makemigrations --check --dry-run
node --check media/js/docsearch.js
```

2026-09-09 本地 PG14–19 快照验证：6,754 个正文页面产生 44,632 个定义与正文片段；全部条目锚点均存在于对应阅读 HTML，来源摘要一致。PG18 的正文段落与代码块覆盖抽查未发现遗漏。126 个版本与代表性查询组合全部命中预期首条，12 个实际阅读页通过 HTTP 与锚点验证。查询样本的服务层 P95 为 24 ms；这是本机样本结果，未包含公网传输，也不是生产压测。索引表及其索引在本次多轮构建后的占用约 218 MB。

49 项搜索与文档回归测试通过。实现支持浅色、深色与窄屏布局，保留邮件列表搜索分支以及原来的文档搜索书签参数。第三方手册仍只提供外链；`ex:` 的 PGEXT 元数据联合检索尚未接入，现有 `/ext/` 目录筛选继续独立使用。

生产发布时，先安装依赖、应用迁移并建立索引，再切换应用代码；如代理缓存了旧阅读页面，应一并刷新对应 `pgdocs_<版本>` 缓存，确保生成的定位锚点已经生效。本次仅完成本地实现与验证，未发布到生产。

当前实体类型按确定性结构提取，尚未穷举所有内部 C API、等待事件、锁模式、操作符类或目录字段。它们的手册正文可全文搜索；结构化成员、补充 GUC 数据集、语义搜索和逐版本差异比较是后续扩展方向。跨版本入口仅表示对应文档中存在同名定义，不推断引入版本、移除版本或运行时可用性。
