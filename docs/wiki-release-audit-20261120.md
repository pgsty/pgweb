# PostgreSQL 19.0 与 PG14–18 最新小版本百科审计

后续修复与发布记录见 [PG19.0 百科校准](wiki-calibration-20261120.md)。本文保留修复前的审计结论、数字及复现证据；当前状态以发布记录为准。

审计日期：2026-11-20。目标为 **PGSQL.CC / pgsql.cc**，本地 `pgweb` 与生产 `/data/app/pgsql.cc` 的 `pgweb` 数据库。

**结论：正式手册、版本元数据与版本比较已经转正；百科仍有四栏默认 PG18、搜索版本范围未过滤百科实体、来源构建滞后、两处已确认的 GA 正文遗漏，以及一批真实的手册链接错误。** 旧来源标签并不意味着所有内容都错：本次已逐项核对的 SQLSTATE、钩子签名、等待事件、函数签名与 SQL 语法概要均未发现集合或语义漂移。

本批修改仅在本地工作区：修正默认版本、搜索跳转版本、手机布局和一个采集器类型别名，并更新维护文档。**未导入业务数据、未改写采样来源、未重建生产索引、未部署生产。** 下面的待校准事项仍然有效。

## 1. 基准与证据范围

覆盖与结果：

- 30 个栏目、35 张百科表；首页所计条目合计 4,771（含版本发布的 31 棵版本树）。35 表所有行排除 `imported_at` 后的内容指纹，本地与生产全部一致。
- 生产运行 `tools/wiki/check_data.sql`，30 栏目的结构、覆盖与派生检索检查通过。六个核心领域另做搜索条目内容核对，差异为零。
- 遍历 PG14–19 快照中的结构化 URL 与 HTML 链接，检查 120,009 条引用记录；601 条原始异常对应 150 个目标，随后逐一甄别展示层影响，不能把原始统计直接叫作坏链接数量。
- 对涉及异常的 426 个实体版本页面实际渲染，402 页仍展示错误目标，共 629 处链接、130 个不同目标。全部修复目标已定位并验证同版本页面与锚点，尚未应用。
- 公网检查 290 个 URL：254 个 200，36 个 404；404 全部来自上述原始手册目标。30 个栏目入口及抽取的逐版本详情均可访问。36 个原始缺页目标中，26 个确实仍出现在渲染页面中。收尾另复验了三个跨版本搜索误命中查询，均可重现。

## 2. 已确认的问题与本地修正

### 2.1 四个栏目默认版本落后：已修本地

`catalog`、`guc`、`waitevent`、`func` 以前用各自采样版本表的 `status='stable'` 选择默认版本，故正式发布后仍打开 PG18，PG19 仍显示“19rc2 为预发行快照，正式发布前仍可能变化”。

直接影响读者：生产不带 `?v=` 的 [max_locks_per_transaction](https://pgsql.cc/wiki/guc/max_locks_per_transaction/) 显示 PG18 的 64；选择 PG19 后实际已有正确的 128。`jit` 在两版的默认值也不同：18 为 `on`，19 为 `off`。

本地新增 `pgweb/wiki/lifecycle.py`，以 `core.Version.current` 选择默认 PG19，支持状态也取软件生命周期。原始 `release`、`server_version`、`documentation_version` 不改写；用 `sample_label` 保留采样标签，在旧采样下显示“已正式发布；本栏采样构建为……，尚未完成 19.0 校准”。列表、详情、变更页共用此逻辑，缓存键同步更新。PG14 显示历史版本，PG15–18 仍受支持，固定 PG20 不变。

其他主题栏、SQL 命令与锁原本已跟随当前版本，本次没有再通过改来源标签来“转正”。

### 2.2 搜索范围到详情页的版本丢失：已修本地

公网 `/search/api/?q=max_locks_per_transaction&scope=pg` 已正确返回 `version=19`，但六个老领域（SQLSTATE、目录、GUC、等待事件、SQL、函数）的实体 URL 不含 `?v=`。从 `pg14:` 搜索打开完整条目同样会回到默认版本；通用预览中的“打开正文”也有该问题。

本地结果 URL 现在携带所选版本，通用预览的打开链接也保留显式版本。API 与无 JS 页面共用同一结果，现有快捷键打开逻辑无需另改。回归测试与实际数据库核验均验证：六个领域在当前版与 PG14 均有快照的样本，其结果与预览打开链接一致。回执在 `local-final-checks.json`。

**仍待修复（高优先级）：百科实体没有按搜索版本过滤。** `pgweb/search/service.py` 中的 SQL 只对手册约束 `e.version`，其余百科实体直接入候选集。因此链接附带版本只解决导航传参，不能保证命中的条目适用于该版本。以下在公网与本地均重现：

| 搜索 | 错误混入的百科条目 | 已收录快照 |
| --- | --- | --- |
| [PG19：abstime](https://pgsql.cc/search/api/?scope=pg19&q=abstime) | 已移除的数据类型 `abstime` | 10、11 |
| [PG14：pg_stat_io](https://pgsql.cc/search/api/?scope=pg14&q=pg_stat_io) | 后续版本才有的系统视图 | 16–20 |
| [PG19：servicefile](https://pgsql.cc/search/api/?scope=pg19&q=servicefile) | 开发版连接参数 | 仅 20 |

全百科集合中，没有所选版快照的实体分别为 PG14：708、15：657、16：569、17：494、18：387、19：246；这些是当前查询条件未排除的潜在候选，并非逐条实际搜索得到的误命中数量，也不把缺少采样一概推断为该版不支持。应在排序、分组、分页和近似查询之前按 `present_in` / 快照身份限制百科候选，或明确另设跨版本搜索入口；不能只在取完一页后丢弃，否则总数与分页会错。来源覆盖不足与实际不存在应继续区分。该问题本批未修改检索筛选逻辑，回执在 `scope-audit.json`。

**仍需优化：** 五个老领域的预览正文仍是通用摘要，并非按 `?v=` 重新生成的事实快照。例如 GUC 搜索摘要还可能包含旧编辑分析中的“设置每个事务的锁数量上限”，与同页准确解释的共享锁表容量不一致。后续应按所选版本生成预览，或者清楚标明通用说明；不要仅追加 URL 就声称预览事实也已逐版本化。

### 2.3 手机横向溢出：已修本地

`max_locks_per_transaction` 的历史说明 chip 使用不换行的 flex 行，两个长英文描述把正文撑宽。实测可用宽度 375px、页面滚动宽度 499px；宽矩阵本身已有独立滚动容器，真正撑宽页面的是描述 chip。

本地让 `.guc-chip` 换行并允许其 `code` 收缩，复看后页面滚动宽度为 375px。保留矩阵自己的横向滚动。桌面深色主题正常，截图在 `tmp/wiki-audit-20261120/pg19-default-desktop.jpg`。

### 2.4 GUC 手册采集器误认 `int`：已修本地

PG14 `max_logical_replication_workers` 的手册类型写作 `int`，现有数据库正确保存 `integer`，但 `guc_importer.DOC_VARTYPES` 未识别此别名，会回退成 `string`。这是采集器问题，不能把审计差异归为手册或现存运行数据错误。

已补 `int → integer`，用现有导入测试中的旧版手册夹具覆盖；六版所有文档化 GUC 的存在集合与已标注类型重新核对，无缺项、无类型冲突。`recovery_target` 的标题使用 `= 'immediate'` 赋值示例，没有类型标记；该项单列为类型证据未提供，不把空值与数据库 `string` 的差异视为错误。没有据此重导任何参数。

| 大版本 | SQLSTATE | 导出钩子 | 等待事件 | 具名函数 | SQL 命令 | 文档化 GUC | 目录字段表已核对 / 已收录关系 |

这些检查分别证明：

- SQLSTATE：六份正式 `errcodes.txt` 的码集合和条件名与数据库吻合，`22P07` 未丢失。它不替代报文案例和运行证据的重新采集。
- 钩子：扫描每版全部 `src/include/*.h`（含子目录），逐个比较导出 hook 身份、typedef 签名与声明，全部相符。PG19 的 `build_simple_rel_hook` 已收录。
- 等待事件：六版手册身份和数据库一致；17–19 再与源码 `wait_event_names.txt` 比对，一致。中文描述差异全部是中英文之间的空格，未发现语义变化。
- 函数：六版当前手册重新抽取后，具名集合与规范签名集合均一致。没有因 PG19 发布凭空新增或删除函数。
- SQL：六版命令集合及中文展示语法概要一致。原始英文 / 中文短语与 `.phrase` 标记差异不作为 SQL 语法变化。
- GUC：六版文档化参数均存在；修正 `int` 别名后，手册明确标注的类型全部相符；`recovery_target` 没有标题类型标记，单列为未提供。PG19 已保存 `jit=off`、`max_locks_per_transaction=128`；`composite_type_mismatch` 的小版本边界与来源标识需要保留。
- 系统目录：定位到字段表的关系，其文档字段与类型一致。`pg_statistic` 的 `stakindN` 等通配写法与数据库 1–5 实际列的差异是表示差异。每版剩余 14 个关系未由本次手册字段抽取覆盖，不能据此宣称全部运行目录已复验。

针对快照直接记录的源码路径与 SHA，另检查了 2,830 个实体版本文件引用：1,931 相同、899 变化。这里比较的是整文件；**899 不等于 899 个错误事实**。PG19 变化集中在锁、计划节点、钩子及解码相关源码，应按具体字段重放；钩子签名已通过上述独立比较。

通用 SQLSTATE 审计还报出 262 个 PG20 手册与运行采样覆盖差异，全部为 `unsampled_devel`；9.0 条件名列的 199 个翻译标签差异，以及 Class 58 的一处空格差异，也均不是本次 PG14–19 错误。
