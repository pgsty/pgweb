## 上线与回退步骤

上线使用同一代码版本：确认 Git 工作区与旧表指纹 → 维护窗口停 `pgsql.cc` → 窗口备份 → 更新代码 → `migrate` → 新旧内容全量比较 → 六来源重建 → `tools/wiki/check_data.sql` → 清理各栏目缓存 → 启动服务 → 验收公网页面。生产单独从生产旧数据转换，不用本地导出覆盖已有生产编辑。

若需要回退，先停止服务并保留新数据备份，使用当前版本代码执行：

```bash
.venv/bin/python manage.py migrate wiki 0006 --noinput
.venv/bin/python manage.py migrate search 0004 --noinput
```

确认八张子表已还原，再部署原代码归档或基线 Git 提交，重新生成六来源检索，启动服务并检查页面。代码与数据库需要成对回退。不要在新 JSON 已产生内容修改后，仅还原早期备份而丢弃新写入。完整备份是逆向迁移之外的恢复手段，不应直接覆盖运行中的数据库。

`CLAUDE.md` 是本机忽略文件，`AGENTS.md` 指向它；本轮更新其当前表结构说明，仓库内可复用的操作契约保存在这些已跟踪文档中。
