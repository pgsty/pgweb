# 博览 PRD

版本：v0.1 · 日期：2026-09-10 · 状态：设计稿

产品归属：PGSQL.CC。本文定义新栏目“博览”的首版范围、内容规则、交互、数据与搜索边界，用于设计评审和实现拆解；当前交付仅为 PRD。

## 1. 产品定义与关键决策

“博览”是 PGSQL.CC 自主管理的中文资讯栏目，以 PostgreSQL 为主，兼顾数据库行业和云计算行业。通过每日筛选、精读摘要与快讯，帮助读者持续了解值得关注的技术与行业变化。

| 项目 | 首版决策 |
| --- | --- |
| 顶部导航 | “博览”，放在“首页”之后 |
| 页面名称 | PostgreSQL 博览 |
| 页面说明 | 每日精选 PostgreSQL、数据库与云计算资讯 |
| 栏目地址 | `/digest/` |
| 内容形式 | 精读、快讯 |
| 默认展示 | 所有已发布内容混排，按本站发布时间倒序 |
| 第二视图 | 每日更新：按日期归档，日内从早到晚阅读 |
| 时间口径 | Asia/Shanghai；原文时间与本站发布时间分开记录 |
| 日常总量 | 全部内容合计目标 10–20 条，默认选题预算 15 条 |
| 精读数量 | 每日最多 10 条；建议通常 3–6 条，不要求凑满 |
| 快讯数量 | 补足当日总量；10–20 条作为快讯为主时的参考规模 |
| 搜索 | 博览独立检索；主站文档检索、搜索弹窗、全文检索均不收录博览内容 |
| 技术落点 | 当前 Django + PostgreSQL；一张内容主表及其专用搜索索引 |

### 1.1 数量口径

需求中同时出现“快讯每天 10–20 条”和“整体每天 10–20 条左右”。本文以最后的整体目标作为设计口径：`当日总数 = 精读数 + 快讯数`，不会把两类额度相加成每日 20–30 条。

例如，5 条精读 + 10 条快讯 = 15 条；8 条精读 + 10 条快讯 = 18 条；没有合适精读时，可以发布 12 条快讯。每日选题按累计已发布数量计算，多次运行 AI 流程不会重复获得一份额度。

精读每日 10 条为发布上限。总量 10–20 条为常规编辑目标：自动选题以 20 条为预算上限；重大事件日可由编辑主动调整当日总预算。页面展示实际发布数量，不按预算截掉已发布条目。质量不足时允许低于 10 条，后台记录原因，不用低质量内容填数。

### 1.2 搜索与公开收录口径

“主站搜索排除”是确定要求，适用于博览自身页面、结果以及博览正文进入其他主站页面后产生的索引副本。原有官网 News、活动等独立模块的检索政策不在本次变更范围内。

公开搜索引擎是否收录博览是另一项策略。本文暂按“允许 Google、百度等发现公开的精读与每日归档”设计；这一默认值待确认，调整它不影响博览与主站搜索的隔离要求。具体页面策略见第 8 节。

## 2. 用户、场景与成功标准

### 2.1 目标读者

- PostgreSQL 开发者与 DBA：关注版本、扩展、工程实践和问题解决方法。
- 数据库与基础设施负责人：关注数据库、云服务的能力、成本和产品变化。
- 社区读者：希望通过一个稳定入口了解近期值得阅读和参与的内容。

### 2.2 核心场景

| 场景 | 用户行为 | 应得到的结果 |
| --- | --- | --- |
| 随手查看最新内容 | 点击顶部“博览” | 直接看到时间倒序的信息流 |
| 每天集中阅读 | 打开“每日更新” | 一页读完所选日期收录的精读与快讯 |
| 补看错过的几天 | 使用左侧日期与月份导航 | 明确哪些天有更新、每天多少条，连续浏览 |
| 找回一条消息 | 在博览搜索框输入关键词 | 只返回博览内容，可限制日期、类型与领域 |
| 深入某篇文章 | 阅读精读后点击“阅读原文” | 到达原作者的实际文章或权威发布页 |
| 分享一条快讯 | 复制该条的永久链接 | 他人无需在历史列表中寻找即可查看 |

### 2.3 产品成功标准

首版首先验证：内容值得读、日期浏览顺畅、更新可持续、搜索严格隔离。运营观察回访、每日归档阅读、原文点击、纠错数量和每批编辑耗时；不把站外点击视作失败，也不把阅读量、点赞量做成未经验证的前台数字。

## 3. 内容策略

### 3.1 三个领域

每条内容有一个主要领域，用于统计和筛选；另可附少量主题或产品标签。一个条目即使同时涉及多个行业，也只计数一次。

| 领域 | 覆盖范围 | 入选原则 |
| --- | --- | --- |
| PostgreSQL | 内核、版本、安全、扩展、驱动、工具、服务、SQL、调优、运维、迁移、社区 | 优先选择，构成栏目的主要内容 |
| 数据库 | 其他数据库的重要发布、架构与工程实践、技术研究、行业变化 | 对数据库从业者有明确价值，优先与 PG 有关联的内容 |
| 云计算 | 数据服务、存储、计算、网络、容器、基础设施产品与价格变化 | 直接影响数据系统的能力、成本或运维选择 |

PG 内容充足时，原则上至少占当日条目的一半；数量不足时，按“PG → 数据库 → 云计算”顺序补充。比例是选题指引，不是强迫填充的发布校验。某天 PG 内容不足时，前台仍按真实领域标记，不把行业消息归成 PG 新闻。

纯消费科技、泛 AI 热点、无实质信息的营销文章、重复宣传稿、与数据基础设施关系很弱的云行业消息，不进入常规收录范围。

### 3.2 候选来源与质量判断

候选来源包括 Planet PostgreSQL、PostgreSQL 官网 News、项目发布页与 Release Notes、维护者博客、工程团队博客、公开开发讨论、会议材料，以及数据库和云厂商的一手公告。现有 Planet 与 News 可提供初始候选，不直接把已有标题批量变成已发布精读。

评估依据是来源可核实、信息增量、技术或行业价值、与读者的关联程度。优先追溯到原始发布者；同一篇文章经多个 RSS 或周刊发现时仅收录一次。

同一次发布或事件的多篇报道可以合并为一条，列出主来源与补充来源。出现新的实质进展时可以另发一条并关联前文；措辞变化、转载和同一消息换链接不构成新事件。

开发讨论、代码合并、测试版、正式版必须区分；性能结论保留版本、环境和负载条件；厂商观点按其主张表述。作者与发布站点分别记录，Planet 等聚合器只作为发现渠道，不替代作者署名。

### 3.3 精读

| 项目 | 要求 |
| --- | --- |
| 中文标题 | 通常 18–36 字，清楚说明内容价值，允许编辑改写 |
| 列表摘要 | 通常 80–140 字，独立撰写，说明最值得关注的内容 |
| 详细摘要 | 通常 350–700 字、3–5 段；内容复杂时可适当延长 |
| 内容组织 | 背景或问题 → 核心发现 → 适用条件与影响 → 值得继续阅读的部分 |
| 图片 | 可选一张封面，缺图不影响发布 |
| 原文入口 | 来源区与正文末尾均提供，主入口文案“阅读原文” |
| 扩展阅读 | 有明确对应关系时链接中文手册、本站扩展目录或相关博览条目 |

精读必须建立在实际阅读来源内容的基础上。只有标题、RSS 截断内容或无法核实的转述时，不生成多段推测性摘要。文字长度是阅读设计目标，不代表版权使用边界。

### 3.4 快讯

快讯采用“短标题 + 一句说明”，整体文案通常 60–100 个汉字，最多 120 字，不含来源与时间。它可以是软件更新、简短行业消息、会议通知或事件进展。

- 不配图，不提供图片占位。
- 不写多段正文，不要求点进详情才能读完。
- 桌面目标为一两行正文；移动端允许自然换行，不通过省略号隐藏关键事实。
- 标题直接链接主来源，以外链标识区分；时间或“复制链接”提供本站永久地址。
- 永久详情保留完整短文、作者或发布者、日期、来源，便于分享和归档；不把快讯扩写成空洞长文。

### 3.5 图片和署名

精读优先使用有明确使用依据且允许外链的 HTTPS 远程封面；许可允许保存时可制作本地副本。没有合适图片时可使用 AI 主题插图、已有主题封面，或不配图。

本地封面统一输出 500×300、5:3 的 WebP；可以通过 FFmpeg 等比例缩放和裁切，重要图表和截图不作随意裁切。远程图片只约束显示比例，不宣称其源文件已转为相同尺寸和格式。

备用图在内容处理阶段准备，浏览器加载失败时直接切换；请求页面时不调用 AI 或 FFmpeg。AI 插图标记“AI 示意图”，不充当真实实验结果、截图或现场照片。图片处理失败不阻塞无图精读。

来源记录保留作者、原题、发布站点、URL，以及需要展示的图片署名和使用依据。公开发表、署名和附上原文链接本身不等于取得使用许可；摘要应独立组织事实与导读，避免连续翻译或逐节压缩原文。参考 [WIPO 版权说明](https://www.wipo.int/en/web/copyright/faq-copyright)。详细编辑与来源政策集中放在关于页或编辑说明中，正文展示与当前内容有关的署名信息。

## 4. 时间、排序、数量与归档规则

### 4.1 时间定义

| 字段或概念 | 含义 | 使用位置 |
| --- | --- | --- |
| 原文发布时间 | 原发布者给出的时间；可能只有日期或未知 | 来源信息、判断时效性 |
| 抓取时间 | AI 流程实际读取来源的时间 | 后台追溯 |
| 本站发布时间 | 条目首次对公众发布的时间 | 常规列表排序、每日归档、每日额度 |
| 本站修订时间 | 条目最近一次公开内容修订时间 | 详情更新信息、缓存和索引维护 |
| 归档日期 | 本站发布时间换算到 Asia/Shanghai 后的日期 | 日期导航、每日计数、日期筛选 |

数据库保存带时区的时间点，按 Asia/Shanghai 计算日期边界。原文只有日期时保留日期精度，不虚构具体时分；原文时间未知时明确标记，不用抓取时间冒充。

### 4.2 排序与修订

- 常规列表：`published_at DESC, uid DESC`。同一时刻以稳定 UID 排序，跨环境回放同一批数据的次序一致。
- 每日更新：固定某个归档日，按 `published_at ASC, uid ASC`，形成从早到晚的当日记录。
- 左侧日期列表：最近日期在前；每个日期的计数来自当天公开条目。
- 精读与快讯混排；类型、领域筛选先限定结果，再按当前视图的时间规则排列。
- 不设置打破时间顺序的置顶，也不用点击热度或 AI 评分重排常规列表。
- 修改标题、摘要、图片或补充来源不刷新首次发布时间，不移入今天的归档。
- 补录旧文章归入实际在本站发布的当天，同时显示原文时间；不回填出并未真实发生的历史发布日。

### 4.3 计数与发布边界

公开列表、每日计数、类型统计、RSS 和博览搜索使用同一公开条件：状态为已发布，且首次发布时间不晚于当前时间。首版不做未来定时发布状态；未到发布时刻的内容保持草稿。

日期导航显示该日全部公开条目数，不随右侧类型或领域筛选变化。筛选后，正文显示“本日共 16 条，当前显示 5 条”，避免把筛选结果误认成当天总量。

撤下条目后从公开计数、列表和搜索中移除。恢复同一条目时保留原 UID 和首次发布时间，回到原归档日，不作为当天新增；它重新占用原归档日的精读额度。类型由快讯改为精读时，同样检查原归档日的精读上限。

## 5. 信息架构与页面要求

### 5.1 地址与入口

| 地址 | 页面或用途 |
| --- | --- |
| `/digest/` | 最新收录，默认全部类型与全部领域 |
| `/digest/daily/` | 302 到最近一个有公开内容的日期 |
| `/digest/daily/YYYY-MM-DD/` | 指定日期的每日更新 |
| `/digest/<entry_id>/` | 单条永久详情；entry_id 使用跨环境稳定的 UUID |
| `/digest/search/?q=...` | 博览独立搜索 |
| `/digest/rss/` | 博览独立 RSS |
| `/digest/sitemap.xml` | 符合公开搜索策略的博览地址清单 |

类型参数统一为 `kind=read|brief`，领域参数为 `domain=pg|database|cloud`，不传表示全部。普通列表支持 `page`；日期导航支持 `month=YYYY-MM`；搜索支持 `q、kind、domain、from、to、sort、page`。`from` 与 `to` 按上海自然日包含首尾两天。

类型与领域切换保留彼此选择，并重置页码。每日视图切换日期保留类型与领域；切换到最新收录时移除具体日期。搜索日期约束必须显示在搜索表单中，不悄悄继承之前浏览的某一天。

所有状态使用真实 URL，刷新、复制链接、前进后退后结果一致。非正整数页码、错误日期格式、日期起点晚于终点等输入应给出明确错误或规范化地址，不能返回模糊的空结果。

### 5.2 最新收录

首屏结构：栏目名称和说明 → 博览搜索框 → “最新收录 / 每日更新”视图切换 → 类型与领域筛选 → 信息流。

左侧日期导航作为归档入口，点击某天进入每日更新。主区每页 20 条，精读与快讯共用一条时间流。日期分隔用于帮助阅读；同一天跨页时明确标注续页，不暗示当日仅有本页这些内容。

精读展示标题、列表摘要、来源和时间，可在右侧放 5:3 小封面；标题进入本站详细摘要。快讯直接展示完整短文和来源外链。不同类型通过文字标记和空间密度区分，不给每类内容使用强烈背景色。

分页采用“更新内容 / 更早内容”或常规页码，保留浏览器返回位置；首版不做无限滚动。新内容到来不在读者阅读中自动插入、挤动页面，刷新后再展示。

### 5.3 每日更新与日期导航

首版采用“左侧日期列表 + 月份选择”，优先展示最近 30 个有公开内容的日期。切换月份后列出该月有更新的日期及数量，提供更早月份入口；无需先做完整的月历网格。

日期导航显示日期、星期、总条数；选中日高亮。日历网格作为后续可选展示方式，未来使用同一份每日计数数据。

当日主区展示：日期、总条数、精读和快讯数量、类型与领域筛选、按时间排列的条目。默认一页展示完整当天，不因常规列表的 20 条分页配置截断；精读在这个视图直接展示详细摘要，快讯直接展示完整短文。

“更早一天 / 更新一天”跳到相邻有内容的归档日，跳过无内容日。URL 直接访问一个合法但没有内容的历史日期时，返回明确的空日页面，保留选中日期并提供相邻有内容日，不静默跳走。未来日期显示“该日期尚未到来”，不返回未公开内容。

今天没有内容时，“每日更新”入口落到最近更新日，并明确显示该日日期；不能把它标成“今日”。当天已发布部分条目时，读者可以立即阅读，页面显示当前数量，不承诺一天必须完成某个数字。

### 5.4 单条详情

精读详情按“标题 → 类型和领域 → 来源信息 → 导语 → 多段详细摘要 → 阅读原文 → 相关链接”组织。图片可选，不强制使用占满首屏的大图。清楚区分原作者与本站编辑，未经人工审核的内容不能显示人工审核署名。

详情页显示所属归档日期并链接到当日条目锚点，锚点使用稳定 UID。修订过的内容显示更新时间；重要事实更正用简短说明记录更正点。

快讯详情只展示其完整短文和来源元数据。快讯列表标题直接跳原文，复制链接指向本站详情；两种动作的用途必须可辨认。首次未发布的 UID 对公众返回 404；已发布后撤下的详情返回不含原摘要的 410 页面，提供回到博览的入口。

### 5.5 移动端与可访问性

移动端把左侧日期导航收起为“选择日期”按钮和当前日期摘要，展开后可选择月份与日期；主区保持单列，不产生页面横向滚动。

精读先展示标题和文字，图片可以缩小或排到后面；快讯完整换行。保留文字标记、键盘焦点、日期按钮可访问名称，日期不能只靠颜色区别是否有内容。主要交互在关闭 JavaScript 时仍可通过表单和链接完成。

### 5.6 视觉规范

沿用 PGSQL.CC 字标、站点蓝色主题、深浅主题及统一顶部横幅，不另造子站品牌。正文主区以清晰分隔线和留白组织，避免大量独立卡片、重复图标和占屏装饰。

建议桌面整体内容宽度约 1100–1200px，日期侧栏 180–220px；详情正文宽度约 680–760px，正文 17–18px、行距约 1.8–1.9。精读列表缩略图约 150–200px 宽，保持 5:3。最终响应式断点与现有页头保持兼容。

## 6. 博览独立搜索

### 6.1 用户体验

栏目搜索框明确标记“搜索博览”，占位提示“搜索文章、作者、软件或行业话题”。它只调用博览搜索。全站页头搜索和 `⌘K` 文档检索保持现有用途；博览不劫持它们，也不向它们添加博览结果。

支持中文、英文、软件名、版本字符串，以及空格分隔的多个关键词。结果可按类型、领域和日期区间筛选；默认相关性优先，提供“最新优先”。结果展示类型、领域、标题、命中摘要、来源和本站发布时间。

精读结果进入精读详情；快讯结果展示完整快讯并进入本站永久详情，另有明确原文外链。无结果时给出调整关键词或清除筛选的入口，不自动回退到主站搜索。

空查询显示搜索表单与当前约束，不执行全库泛搜索；浏览全量内容使用“最新收录”。默认每页 20 条，分页保留完整查询条件。输入长度限制为 200 字符，中文输入法组合期间不发送搜索请求。

### 6.2 索引范围与排序

可检索字段包括中文标题、原题、列表摘要、详细摘要、作者、发布站点、产品和主题标签。图片提示词、审核信息、内部质量评分、抓取日志、未公开原文副本不参与公开检索。

优先匹配标题、产品名和标签，其次是摘要与正文；来源、作者匹配仍能找到相关条目。正文长度不应天然让精读压过更直接命中的快讯。相关性相同时按本站发布时间倒序，再以 UID 稳定排序。

日期筛选基于本站发布时间及上海自然日，与每日归档完全一致。原文时间只作展示，首版不再增加第二套日期筛选。

### 6.3 技术建议与独立性定义

首版在 `digest_entry` 上维护专用 `search_vector` 和 GIN 索引，提供独立查询服务与 `index_digest` 重建命令。继续使用现有 PostgreSQL，不新增独立搜索服务器。

中文分词可复用现有实现的纯文本处理能力，并为数据库与云计算领域补充独立词典；博览不修改主站词典的运行状态，也不复用主站搜索模型、来源枚举和查询结果缓存。当前混合中英文分词可参考 [lexicon.py](../pgweb/search/lexicon.py)。

正文、发布状态和检索字段在同一发布事务中更新；失败时该次发布或编辑不产生半完成状态。草稿与已撤下内容的检索字段清空，索引只服务公开状态。重建命令支持增量、强制重建和预览，记录索引版本。

独立的验收含义是：博览拥有自己的数据范围、检索字段、数据库索引、查询入口、排序、缓存与维护命令；重建博览不会清空或改写主站索引。只给主站共用索引增加一个可选过滤参数不符合本需求。

## 7. 主站搜索隔离

### 7.1 必须覆盖的入口

| 主站入口或数据 | 隔离要求 |
| --- | --- |
| `/search/` 文档检索 | 不包含博览条目或摘要 |
| `/search/api/` 与检索预览 | 不返回博览条目，不产生博览来源类型 |
| 全站 `/`、`⌘K` 搜索弹窗 | 结果和自动补全不包含博览 |
| `/search/?site=1` 全文检索 | 不包含博览，包括显式限制到博览路径的查询 |
| `search_indexedpage`、`search_searchentry` | 不写入博览数据 |
| `webpages` 主站爬虫索引 | 不存储博览页面及通过主站页面带入的博览正文 |
| 主站推荐搜索、缓存及日后新增搜索入口 | 沿用相同边界，不能通过兜底重新并入 |

### 7.2 当前代码带来的约束

当前 [SitemapSiteCrawler](../tools/search/crawler/lib/sitemapsite.py) 会读取 `/sitemap.xml` 和 `/sitemap_internal.xml`，并明确忽略 robots.txt。公共 sitemap 又会通过 [sitestruct.py](../pgweb/util/sitestruct.py) 汇集应用的 `get_struct()` 输出。因此，仅把博览从内部 sitemap 去掉，或仅设置 robots.txt，均不足以满足主站搜索隔离。

当前 [GenericHtmlParser](../tools/search/crawler/lib/parsers.py) 还会提取 body 中的大部分文字。若首页直接展示博览标题和摘要，即使博览 URL 没被爬取，内容仍可能通过首页进入 `webpages`。

### 7.3 实现要求

1. 主站爬虫统一排除 `/digest` 与 `/digest/` 下的所有路径，包括列表、日期归档、详情、搜索、RSS 和接口。判断基于规范化后的本站路径，不误排其他目录。
2. sitemap 的跳过逻辑必须位于 lastmod 短路处理之前；否则旧记录可能被计作已经扫描而保留下来。实际抓取入口也应应用同一排除规则，覆盖重定向和后续新增抓取入口。
3. 主站检索查询在数据库过滤阶段排除博览路径，覆盖 `site_search()` 的普通查询与 suburl 查询两条分支，命中计数与分页使用同一过滤条件，不能取回结果后仅在前端隐藏。
4. 上线时检查并清理已存在的误收录条目，以及此前包含博览摘要的主站页面索引；先报告影响范围，执行后验证博览路径残留为零。
5. 博览不通过 `get_internal_struct()` 暴露给主站内部 sitemap。独立公开 sitemap 与主站索引职责分开，公开可抓取不意味着本站全文搜索可索引。
6. 首版首页只保留通向“博览”的栏目入口，不在首页复制具体条目摘要。若后续增加首页精选，必须先实现并验证主站爬虫忽略指定博览区块，之后再展示标题、摘要与图片说明。

这些措施分别解决内容进入索引、历史残留和查询可见性，不以降低搜索权重、客户端隐藏、`nofollow` 或外部搜索引擎的 `noindex` 替代。

生产存在两站共用搜索数据库的环境。落实时需核对实际运行的爬虫目录与配置；当前操作约定提到的旧站爬虫入口也必须具备排除规则。不能只更新新站应用目录就宣称主站爬虫已经完成隔离，也不通过改动共享 `sites.id=1` 的域名归属来实现隔离。

## 8. 公开搜索引擎与订阅

### 8.1 默认公开收录策略

以下是等待确认的公开搜索策略；它始终不改变第 7 节的主站隔离要求。

| 页面 | 默认公开搜索策略 |
| --- | --- |
| 博览首页 | 可收录，canonical 指向 `/digest/` |
| 已发布精读详情 | 可收录，canonical 指向本站永久详情，原文通过来源链接表达 |
| 有内容的每日归档 | 可收录，canonical 指向不带筛选参数的日期地址 |
| 快讯永久详情 | `noindex,follow`，保留用户访问和分享；内容通过每日归档被发现 |
| 搜索结果、筛选组合、分页变体、空日期与未来日期 | `noindex,follow`，不加入公开 sitemap |
| 草稿、后台、预览、已撤下内容 | 不公开或禁止收录 |

`/digest/sitemap.xml` 只列博览首页、公开精读和有内容的日期归档，可单独通过 robots.txt 的 Sitemap 声明被发现，不要求把条目加入主站默认 sitemap。主站爬虫无论遇到哪份 sitemap，都继续排除博览路径。

如果确认也禁止 Google、百度等收录，则公开博览页面统一提供适用的 `noindex` 信号，并停止公开 sitemap 的发现声明。不能一边依赖爬虫读取 `noindex`，一边通过 robots.txt 阻止其访问：Google 的 [noindex 文档](https://developers.google.com/search/docs/crawling-indexing/block-indexing) 明确说明了这一限制。此策略约束支持相关规则的搜索引擎，不构成访问控制。

### 8.2 RSS

首版提供独立 RSS，默认最近 50 条公开条目，顺序与常规列表一致。每条使用稳定 UID 生成 guid，发布时间使用本站首次发布时间，编辑后不更换 guid、不重新作为新条目推送。

RSS 链接指向本站永久详情；精读输出导语或摘要，快讯输出完整短文，两者都附原文链接和来源。撤下内容不再出现在后续 feed 中；不承诺撤回订阅器已经缓存的历史副本。每日归档 RSS、邮件推送和外部社交平台分发不在首版范围内。

## 9. 数据模型建议

一张 `digest_entry` 作为博览内容的唯一主表，兼容精读和快讯；检索字段在同表维护专用索引。来源登记先用配置文件，多个内容来源用结构化 JSONB，暂不增加作者库、来源管理平台或独立日报主表。

| 字段组 | 建议字段 | 约束或用途 |
| --- | --- | --- |
| 身份 | `uid`、`import_key` | UUID 跨环境一致；import_key 唯一，用于幂等更新 |
| 内容 | `kind`、`title`、`summary`、`body` | read 为精读、brief 为快讯；快讯 body 为空，summary 即完整短文 |
| 分类 | `domain`、`tags` | 一个主要领域，少量主题与产品标签 |
| 来源 | `primary_url`、`sources` | sources 保存原题、作者、发布站点、语言、来源时间和引用关系 |
| 去重 | `canonical_source_url`、`event_key` | URL 去重与事件合并；事件键可空，由编辑或流程确认 |
| 时间 | `source_published_at`、`source_time_precision`、`fetched_at`、`published_at`、`updated_at` | 原文日期精度单独保留；归档日从 published_at 推导 |
| 图片 | `cover_url`、`cover_path`、`cover_kind`、`cover_alt`、`cover_credit`、`cover_rights` | 图片文件不存数据库；快讯图片字段为空 |
| 编辑 | `status`、`editor`、`manual_locked` | draft / published / withdrawn；保护人工改动 |
| 生成记录 | `generation_meta`、`content_hash` | 生成版本、批次、质量判断依据、必要核对结果；仅后台可见 |
| 检索 | `search_vector`、`search_revision`、`search_updated_at` | 博览专用，不写入主站索引表 |

主来源必须存在，正文不得把未抓取成功的来源伪装成已经阅读的材料。来源时间以每个来源记录为准，主字段只便于列表展示。对外不展示内部评分和生成日志。

建议索引包括 UID / import_key 唯一索引、公开状态与发布时间排序索引、精读和领域筛选需要的组合索引、搜索向量 GIN 索引。日期查询使用上海日界转换后的时间范围，不在所有查询中逐行格式化日期。

每日归档由内容实时聚合或短期缓存形成，不复制正文，不另外维护可能失真的新闻篇数。所有发布与修订入口共用内容校验和检索更新逻辑；后台直接编辑同样生效。

## 10. 编辑与 AI 更新流程

### 10.1 流程

~~~mermaid
flowchart LR
    A[发现候选] --> B[URL 与事件去重]
    B --> C[读取原文并核对事实]
    C --> D[选领域与类型，计算当日预算]
    D --> E[编写精读或快讯，处理可选封面]
    E --> F[形成固定批次与预览差异]
    F --> G[按发布规则写入]
    G --> H[同步正文与独立索引，刷新日期和订阅]
~~~

AI 可以每天执行一次或多次，先查看已有条目、当天已发布数量和未完成批次，再处理增量。来源读取失败、关键信息冲突和来源使用条件不明时保留待处理状态，不以生成流畅度替代事实核对。

前期建议生成草稿后集中校阅；对可信来源、格式稳定的快讯，可以在发布规则明确后自动发布。首版不硬编码模型厂商，也不要求新建复杂调度系统，提供可被现有外部 AI 流程调用的导入接口即可。

### 10.2 输入与发布契约

一个固定批次包含：批次 ID、生成时间、稳定 UID、导入键、内容、来源、精度明确的日期、预定发布类型与领域，以及本地图片文件和校验信息。预览展示新增、无变化、建议修改、重复、需要处理的来源和当日额度变化。

先预览、后写入；重复执行同一批次不产生新 UID、不增加日期计数、不刷新旧发布时间。对于已经发布或人工修改过的条目，自动流程产生修改建议，默认不覆盖；明确执行修订后仍更新原条目。

无关或低质量候选可以留在批次记录中，不进入公开表；需要后续编辑的候选以草稿保存。初期用本地与生产现有 Planet / News 识别候选边界，重新核实原始来源，不复制上游数据库的本地自增 ID 作为全局身份。

本地与生产使用同一固定批次、UID 和图片文件，分别核验新增、修改、跳过和失败数量。已经成功的一端无需重写；另一端失败可用相同批次重试。一次导入的失败不能让公开正文、独立搜索与日期计数相互矛盾。

### 10.3 状态与后台

草稿可以发布；已发布可以修订或撤下；已撤下可以在保留历史身份和日期的前提下恢复。草稿与撤下条目不出现在任何公开列表、日期计数、搜索和 RSS 中。

后台提供类型、领域、日期、状态筛选，支持预览、编辑、批量发布与撤下。显示当日精读和总量预算、来源信息、图片来源、生成批次和人工锁定情况。无需新增公开投稿、评论、点赞或读者账号系统。

## 11. 非功能要求与运行边界

- **规模**：按每日上限 20 条估算，约 7,300 条/年；首版按 5 万条公开数据评估列表、归档和检索，不为此引入额外搜索集群。
- **性能目标**：在约定的测试环境、5 万条数据、索引完成且服务预热后，常规列表、日归档与搜索的服务端 P95 目标不超过 500ms；报告测量条件，浏览器外网图片耗时单独记录。
- **一致性**：发布、修订、撤下后，详情、日期计数、列表、RSS 与搜索应同步失效缓存。撤下内容不能仅在页面隐藏而仍被搜索或详情接口读取。
- **阅读可用性**：图片缺失、加载超时和 AI 流程失败不影响既有内容阅读；明确图片尺寸，避免加载后挤动文字。
- **渲染**：复用现有 Markdown 清洗与外链处理；正文不能执行来源站点脚本。CSS、JavaScript 按项目 CSP 要求放到静态资源，不能依赖内联事件回调。
- **维护**：博览独立索引可从内容表重建；日报数量可从发布时间重新聚合；不依赖源网站在每次访问时在线。
- **观察**：记录每批候选、去重、入选、发布、失败、人工修改冲突和处理耗时，足够定位遗漏与重复即可，不先建设专门运营看板。

以下均为实施后的验收要求，不表示已经完成开发或测试。

| 编号 | 场景 | 通过条件 |

| TYPE-02 | 快讯阅读 | 无图片和占位，列表可读完完整短文；外链与本站分享链接可辨认 |
| DAY-01 | 23:59 与次日 00:00 发布 | 按 Asia/Shanghai 分属正确日期，计数、搜索日期筛选和日额度一致 |
| DAY-02 | 单日、多日、跨月浏览 | 日内从早到晚；日期导航从近到远；相邻有内容日跳转正确 |
| DAY-03 | 无更新日期与未来日期 | 显示真实空状态；不显示草稿，不把旧内容标成今日 |
| DAY-04 | 类型和领域筛选 | 导航仍显示当天总数，正文另显示当前筛选数量 |
| DAY-05 | 当天超过常规总量预算 | 每日页面展示完整已发布内容，不因 20 条分页配置丢失尾部 |
| QUOTA-01 | 同日多批执行 | 累计计算条数，精读超过 10 条的新增发布被拒绝；重复批次不消耗新额度 |
| IMPORT-01 | 原文通过多个来源出现 | 同一 URL / 事件不重复发布；保留真实作者和主来源 |
| IMPORT-02 | 人工修改后重复导入 | 人工内容保留，冲突有记录，旧发布时间不变 |
| SEARCH-01 | 中文、英文、软件名、版本组合 | 独立搜索能找到精读和快讯，类型与日期过滤准确，标点不破坏查询 |
| SEARCH-02 | 草稿、修订、撤下、恢复 | 可见性与内容同步，撤下后旧摘要不可被检索，恢复仍属于原归档日 |
| ISO-01 | 仅在博览正文中设置唯一测试词 | 博览搜索命中；主站检索页面、API、弹窗、site=1 均不命中 |
| ISO-02 | 主站全文搜索指定博览 suburl | 仍无博览结果，命中总数与分页不泄漏条目 |
| ISO-03 | 公共或内部 sitemap 意外包含博览 | 主站爬虫仍跳过，包括 lastmod 未变化的旧记录；重复运行不重新收录 |
| ISO-04 | 主站曾误收录博览路径或首页摘要 | 清理或重抓后不存在博览正文残留；已有文档和正常主站检索不受影响 |
| ISO-05 | 生产实际爬虫来自旧站目录 | 实际执行入口已包含排除规则，不能只以新站代码修改作为证据 |
| MEDIA-01 | 远程图失败、没有许可图、生成失败 | 使用可用备用图或无图排版；不出现持续破图，不触发访客侧生成 |
| CACHE-01 | 发布、撤下或恢复 | 列表、详情、日期数、RSS 与搜索同步反映状态 |
| SHARE-01 | 快讯与精读分享、正文修订 | 永久 UID 与 URL 不变；RSS guid 不变，原文链接可达或有后台异常记录 |
| SEO-01 | 公开收录策略 | canonical、noindex 和 sitemap 与所选策略一致，且不削弱主站隔离 |
| A11Y-01 | 320px、390px 与桌面 | 无横向溢出，标题和快讯信息完整，日期选择可键盘操作 |
| PERF-01 | 约定规模性能测试 | 记录环境与样本，列表、日归档、独立搜索达到第 11 节目标 |
| SYNC-01 | 同一批次导入本地与生产 | UID、内容和图片校验一致，各端新增、跳过与失败分别可核验 |

## 14. 实施拆解与依赖

1. **内容基础**：新增 `pgweb/digest`、主表、后台、内容和额度校验、固定 UID 导入契约。
2. **阅读功能**：顶部导航、最新列表、日期归档与月份导航、详情、类型和领域筛选、响应式样式。
3. **索引与隔离**：独立分词与查询、索引重建命令、主站爬虫排除、主站 SQL 查询过滤、误收录清理方案。
4. **更新流程**：固定批次预览与导入、人工保护、图片处理、RSS、索引与缓存同步。
5. **发布验收**：在隔离测试数据上验证日期边界和独有关键词；核对实际生产爬虫入口，再按明确发布范围部署。

搜索隔离、发布可见性与日期计数是上线必需项，不能在先公开内容后再补。实施阶段适合的验证数据应覆盖精读、快讯、跨日、跨月、零条日期、撤下和重复来源；本 PRD 不要求现在创建种子数据或运行 AI 试点。
